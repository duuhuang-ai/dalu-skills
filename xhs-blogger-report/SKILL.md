# 小红书博主账号分析报告

从飞书多维表格读取笔记数据，生成结构化 Markdown 分析报告。

## 前置条件

- lark-cli 已安装并完成认证
- lark-base skill 已安装

## 输入

用户提供一个飞书多维表格链接，格式如：
- `https://xxx.feishu.cn/base/{token}?table={table_id}&view={view_id}`
- `https://xxx.feishu.cn/wiki/{token}`（Wiki 链接需先解析）

## 表格字段要求

| 字段名 | 类型 | 必需 | 用途 |
|--------|------|------|------|
| 笔记标题 | text | ✅ | 爆款分析、情绪词提取 |
| 点赞数 | number | ✅ | 互动排名、爆款率 |
| 收藏数 | number | ✅ | 赞藏比 |
| 评论数 | number | 建议 | 用户互动焦点（缺失时降级） |
| 账号粉丝数 | number | ✅ | 粉丝规模评估 |
| 笔记标签 | select(多) | ✅ | 内容集中度 |
| 笔记内容 | text | ✅ | 人设、风格分析 |
| 发布时间 | text | ✅ | 发布节奏 |

缺少"建议"类字段时对应章节降级标注，不影响报告生成。

## 执行流程

### 第1步：解析链接

从用户提供的链接中提取 base_token 和 table_id：
- `/base/{token}?table={table_id}` → base_token = token, table_id 从 URL 参数取
- `/wiki/{token}` → 先 `lark-cli wiki spaces get_node --params '{"token":"<wiki_token>"}'`，取 `obj_token` 作 base_token
- URL 中 `?table=` 的值：`tbl` 开头为 table_id，`blk` 开头为 dashboard_id（不应作为 table_id）

### 第2步：读取表结构和数据

```bash
# 读取字段结构
lark-cli base +field-list --base-token <token> --table-id <table_id>

# 读取记录（默认200条，检查 has_more 决定是否翻页）
lark-cli base +record-list --base-token <token> --table-id <table_id> --limit 200
```

#### ⚠️ 字段映射（关键步骤）

`+field-list` 返回的字段顺序和 `+record-list` 返回的数组下标**不一定一致**。`+record-list` 会跳过 `not_support` 和 `attachment` 类型的字段。因此：

1. 从 `+field-list` 结果中过滤掉 `type=not_support` 和 `type=attachment` 的字段
2. 用过滤后的字段列表建立 `field_name → 数组下标` 的映射表
3. 用映射表从记录数组中按名称取值

**映射验证**：建完映射后，用第一条记录的实际值验证映射是否正确（如"笔记标题"字段值应该是文字、"点赞数"应该是数字、"账号粉丝数"应该是万级数字）。如果值类型不匹配，说明映射有误，需要重新校验。

**绝对不要硬编码数组下标**，不同表格的字段配置不同，硬编码会导致字段错位。

### 第3步：数据分析

基于读取的数据，按以下维度分析：

#### 维度1：内容数据概览
- 总笔记数
- 粉丝数
- 爆款率：>100赞、>200赞、>500赞各占比
- 赞藏比：总点赞÷总收藏，判断内容工具属性
- 总评论数 + 平均每篇评论数
- 内容集中度：按标签分组统计，重点统计邮轮/船只/目的地类标签

#### 维度2：爆款内容剖析
- 互动量 TOP10 排名（按点赞+收藏排序，含评论数）
- 关键发现：
  - **收藏>点赞**的笔记：列出标题+数据，说明工具属性强
  - **评论>点赞**的笔记：列出标题+数据，说明用户咨询需求旺盛
- 超级爆款拆解：标题要素、选题类型、内容形态、核心驱动力
- 爆款公式提炼：身份标签 + 核心痛点 + 情绪触发 + 行动承诺
- 选题类型排序：按标签+互动量分组，计算各类平均互动

#### 维度3：标题情绪词频
统计标题中出现的情绪词，分类为：
- 紧迫感（"必看"、"千万别"、"太香了"、"听劝"）
- 揭秘感（"信息差"、"真相"、"揭秘"、"没人说"）
- 反常识（"不是你想的那样"、"智商税"、"拉垮"）
- 共情承诺（"谁懂啊"、"狂喜"、"太香了"、"真的"、"实在"）
- 行动指令（"直接抄"、"看完秒懂"、"一镜到底"、"全搞定"、"避坑指南"）

统计各类出现次数，标注哪类词频最高及对应语言风格特征。

#### 维度4：人设推断
从标题和内容推断：
- 功能定位（避坑/种草/科普）
- 内容形态（攻略/体验/测评）
- 语言风格（口语化程度、emoji使用、句式特征）
- 差异化点：总结"不做XX，而是XX"的定位差异

#### 维度5：整合评分
| 维度 | 评分方法 |
|------|----------|
| 内容垂直度 | 标签集中度（前3标签占比） |
| 爆款能力 | >100赞笔记占比 |
| 粉丝质量 | 赞藏比（>2.0为健康）+ 评论活跃度（平均评论数）+ 评论>点赞占比 |
| 更新频率 | 发布时间间隔中位数 |

### 第4步：输出报告

按以下模板输出 Markdown 报告。**降级处理**：数据不足的章节标注原因，不跳过。

## 注意事项

- **字段映射必须动态**：过滤 not_support/attachment 字段后建立名称→下标映射表，并用第一条记录的值验证映射正确性。不同表格的字段配置不同，硬编码下标会导致字段错位
- **映射验证方法**：取第一条记录，检查每个关键字段的值类型是否与字段名语义匹配（如"点赞数"应该是数字、"笔记标题"应该是文字、"账号粉丝数"应该是万级数字）。不匹配时重新校验映射
- 赞藏比 < 1 时说明收藏 > 点赞，内容工具属性极强，值得关注
- **评论>点赞**是关键信号：说明用户有明确咨询需求而非仅浏览，必须在报告"关键发现"和"策略建议"中体现
- 评论数全为空时，在报告顶部注明"评论区数据缺失"，策略建议中不基于评论推断
- 爆款率阈值根据样本量调整：样本<30篇时，>100赞即为爆款；样本>50篇时，>200赞为爆款
- 发布时间格式不统一时，先尝试解析，解析失败的记录标注"时间格式异常"
- 报告保存到当前工作目录，文件名格式：`{账号名}账号分析报告.md`
- TOP排名至少列出10条，让用户看到完整的头部+腰部分布
