# 小红书虚拟选品诊断（xhs-virtual-selection-diagnosis）

> 一个面向小红书商家的选品决策 Skill：你给它一个虚拟商品链接、或手动填几项商品信息，它帮你判断**值不值得做、怎么改造成自己的产品、上架前要规避哪些风险**，并产出一份可直接打开的独立 HTML 诊断报告。

* * *

## 核心能力

读取商品信息 → 判断商家决策 → 拆解爆品逻辑 → 指出不可照搬之处 → 给改造方向与上架包装建议 → 生成独立 HTML 诊断报告。

## 适用场景

| 场景 | 说明 |
| --- | --- |
| 跟品决策 | 看到同行在卖的虚拟商品，判断自己要不要跟、怎么跟 |
| 选品评估 | 手里有候选品，用结构化维度快速排出优先级 |
| 改造灵感 | 参考品不能直接抄，需要 3 个可落地的「自己的版本」方向 |
| 上架前体检 | 标题、详情页、交付物、承诺措辞、售后一键风险自查 |
| 团队对齐 | 把判断沉淀成一份可分享的 HTML 报告，运营 / 供应链同看 |

## 快速安装（Codex / WorkBuddy）

把下面这段命令复制到 **Codex** 或 **WorkBuddy** 的终端执行即可（目录名即 Skill 名，必须保持中文 `小红书虚拟选品诊断`）：

```bash
git clone https://github.com/duuhuang-ai/dalu-skills.git ~/.workbuddy/skills/小红书虚拟选品诊断
```

执行后**重载 / 重启会话**，Skill 即以「小红书虚拟选品诊断」生效。

> **Codex 用户**：把目标路径换成 Codex 的 skills 目录即可（目录名不变）。

## 依赖与准备

本 Skill 是**代理驱动（agent-driven）**的，不强制依赖外部脚本或密钥：

1. **运行环境**：WorkBuddy / Codex 等支持 Skill 的 Agent 环境。
2. **商品链接模式**：需要 Agent 能打开小红书商品详情页（浏览器能力 + 可访问小红书的网络环境）。读不到时自动降级为手动信息模式。
3. **手动信息模式**：只需用户填「商品名称 / 类目 / 价格 / 销量」四项，无需任何外部依赖。
4. **报告产出**：在本地可写文件时，Skill 生成独立 `.html` 报告；不可写时退化为对话内 Markdown 摘要。

无需 `lark-cli`、无需 API Key、无需选品库文件。

## 使用方式

### 触发词

`小红书虚拟选品诊断`、`虚拟选品诊断`、`选品诊断`、`这个虚拟品值不值得做`、`帮我校验选品`、`上架前选品体检`，或直接发送小红书商品链接 / 粘贴商品信息。

### 输入方式 A：商品链接

直接把小红书商品详情链接发给 Agent：

```
用「小红书虚拟选品诊断」帮我看看这个品值不值得做：
https://www.xiaohongshu.com/goods/xxxxx
```

Agent 会读取公开商品页，抓标题、价格、销量、店铺、主图文案、详情页卖点；读不到时只向你补问最少必要字段。

### 输入方式 B：手动商品信息

没有链接也能用，发一段结构化信息即可：

```
用「小红书虚拟选品诊断」评估：
- 商品名称：小红书爆款标题生成器
- 商品类目：虚拟资源 / 工具
- 商品价格：39.9
- 商品销量：月销 2000+
- 交付方式：网盘自动发货
- 目标人群：自媒体运营新手
```

## 诊断工作流

1. **提取事实**：先抓商品可见信息，区分「观察到的事实」与「推断」。
2. **补齐必填**：最少必要信息缺失且读不到时，只追问「名称 / 类目 / 价格 / 销量」。
3. **下决策**：先给**推荐做 / 改造后再做 / 不建议做**三选一判断。
4. **解释判断**：用商家语言说清需求、销量、价格、竞争、交付难度、平台风险。
5. **拆解爆品**：用户痛点是什么、参考品到底在卖什么、价格带与交付物是什么。
6. **划红线**：指出版权素材、课程资料搬运、题库 / 答案、软件授权、AI / PS / 字体素材、过度承诺、自动发货纠纷、敏感词、资质等绝对不能照搬之处。
7. **给方向**：3 个商家自己能做出来的改造方向，而非抄版。
8. **上架包装**：标题方向、封面卖点、套餐结构、详情页大纲、发货说明、售后说明。
9. **出报告**：生成独立 HTML 诊断报告（可基于 `references/report_template.html` 套样式）。

## 评分维度

用 1–5 分，方向清晰：机会类越高越好，风险 / 难度类越高越差。

| 维度 | 含义 | 方向 |
| --- | --- | --- |
| 需求强度 | 目标人群的真实痛点强度 | 高 = 好 |
| 增长潜力 | 仅在有近期趋势数据（近 7/30 天销量增长或日销追踪）时打分；无数据则省略 | 高 = 好 |
| 价格合理度 | 当前定价相对价值与竞争的合理性 | 高 = 好 |
| 差异化空间 | 你能做出与他人不同的空间 | 高 = 好 |
| 交付难度 | 你实际交付的复杂度与稳定性风险 | 高 = 差 |
| 违规风险 | 平台下架 / 违规的样本风险 | 高 = 差 |

> 平台风险分析**不是官方规则解读**，是基于样本与内容风险的判断，报告中会明确标注。

## HTML 报告结构

报告命名优先用「小红书虚拟选品诊断」（不用「诊断报告」），必含 10 个章节：

1. `最终判断`：推荐做 / 改造后再做 / 不建议做 + 一句话
2. `商品基础信息`：名称、类目、价格、销量、来源类型、图片 / 链接
3. `机会评分`：评分表或卡片
4. `为什么这么判断`：务实解释
5. `爆品拆解`：用户为什么买、参考品在卖什么
6. `不能照搬的地方`：风险与不可复制部分
7. `怎么改成自己的产品`：3 个具体改造方向
8. `上架包装建议`：标题、封面、套餐、详情页、发货、售后
9. `上架前风险检查清单`：标题、详情页、交付物、版权 / 授权、承诺措辞、售后
10. `下一步动作`：今天就能做的 5–8 个动作

报告为独立 HTML，内联 CSS，不依赖外部资源，可直接用浏览器打开或分享。

## 关键执行边界（Hard Rules）

- 只评估用户提供的商品详情页与商品信息，不采集达人主页、笔记页、评论。
- 不仅凭链接去自动匹配本地选品库 / 历史导出 / Downloads 文件，除非用户明确要求。
- 公开商品页读不到时，改为索取「名称 / 类目 / 价格 / 销量」，不静默混入本地数据。
- 不把平台风险包装成官方规则解读。
- 不给用户索要后台字段（是否已下架、平台提示原因、搜索关键词等），除非用户已提供。
- 在小红书页面不要停在空 DOM 快照，先尝试截图可见提取再判断字段缺失。
- 报告为独立 HTML，不依赖外部资源，除非用户明确要求。

## 故障排查

### 商品链接读不到

可能原因：商品已下架、设为不可访问、网络无法访问小红书、页面结构变化、平台风控导致公开信息不全。

处理：Agent 会自动降级为「手动信息模式」，只向你补问名称 / 类目 / 价格 / 销量。

### 小红书页面 DOM 为空

原因：SPA 页面快照为空，但视觉已加载。

处理：优先用截图提取可见信息；截图仍缺必填字段时，再向你追问。

### 报告没生成

原因：当前环境不可写本地文件。

处理：Skill 退化为对话内 Markdown 摘要；换到可写文件的环境（如本地 Codex / WorkBuddy）即可生成 HTML。

### 评分出现「信息不足」

这是**不该出现**的情况。增长潜力等趋势类维度，在没有数据时**直接省略**，不显示占位卡或「信息不足」。

## 完整检查清单

开始前逐项确认：

- 已给商品链接或手动填了「名称 / 类目 / 价格 / 销量」
- 链接是小红书商品详情页（非笔记页 / 账号页）
- 需要趋势分（增长潜力）时，已提供近 7/30 天销量增长或日销追踪数据
- 当前环境能打开小红书商品页（链接模式）
- 需要 HTML 报告时，环境可写本地文件
- 已明确是否要用本地选品库参与评估
- 收到报告后，已按「上架前风险检查清单」自行复核最新社区规范
